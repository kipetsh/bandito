# Настольное и мобильное приложение

Bandito можно запускать как отдельное приложение на macOS, Windows и Android. Нативная оболочка использует Tauri 2, а интерфейс и игровая логика остаются общей веб-кодовой базой Vite.

## Команды

| Команда                     | Назначение                                                 |
| --------------------------- | ---------------------------------------------------------- |
| `npm run app:dev`           | Запуск приложения в режиме разработки                      |
| `npm run app:build`         | Сборка приложения для текущей платформы                    |
| `npm run app:icons`         | Генерация системных иконок из `src-tauri/icons/source.svg` |
| `npm run app:android:init`  | Первичная генерация Android-проекта                        |
| `npm run app:android:build` | Сборка Android APK                                         |

## Требования

- Node.js 22.12 или новее.
- Rust stable.
- Для macOS — Xcode Command Line Tools.
- Для Windows — Microsoft C++ Build Tools и WebView2.
- Для Android — Android Studio, JDK 17, Android SDK, Build Tools и NDK.

Android-проект создаётся командой `npm run app:android:init`; сгенерированная папка `src-tauri/gen/` не хранится в Git и создаётся заново в CI. Для работы Android Gradle/Rust-плагина также обязателен скрипт `tauri` в `package.json`: сгенерированный Gradle-проект вызывает его через `npm run tauri`, передавая аргументы сборки. Не удаляй этот скрипт и сохраняй его вызов через закреплённую версию Tauri CLI.

## Сборка приложений вручную

Workflow `Build Bandito apps` при push в `main` только публикует OTA (см. [ci.md](ci.md)). Дорогие нативные сборки не запускаются автоматически: desktop и Android jobs выполняются только при ручном запуске через **Actions → Build Bandito apps → Run workflow** с `build_apps = true`. Ручной запуск собирает macOS Apple Silicon, macOS Intel и Android APK, а затем создаёт общий ZIP. Сборки Windows x64 в workflow сейчас нет. Артефакты доступны в разделе Artifacts соответствующего запуска и хранятся 14 дней.

Android APK подписывается постоянным release-ключом. Перед первой Android-сборкой нужно один раз создать keystore локально и сохранить его в GitHub Actions Secrets — сам файл keystore нельзя добавлять в репозиторий:

```bash
keytool -genkeypair -v -keystore bandito-release.jks -alias bandito -keyalg RSA -keysize 2048 -validity 10000
base64 -i bandito-release.jks | pbcopy
```

В GitHub открой Settings → Secrets and variables → Actions → New repository secret и добавь три секрета:

- `ANDROID_KEY_BASE64` — вставь содержимое буфера обмена после команды base64.
- `ANDROID_KEY_PASSWORD` — пароль, заданный при создании keystore.
- `ANDROID_KEY_ALIAS` — `bandito`.

Workflow восстанавливает keystore во временной папке runner, настраивает Gradle release signing и собирает подписанный APK. Не публикуй keystore и не передавай пароль в чат. Сохрани keystore и пароль в надёжном месте: для всех будущих обновлений Android необходимо использовать тот же ключ. Если потерять его, обновить уже установленную сборку поверх старой не получится.

Сборки macOS и Windows пока не подписаны сертификатами разработчика. Для распространения macOS вне локального тестирования понадобятся подпись и notarization.

## Как работают приложения и обновления

Нативные версии Bandito — это оболочка Tauri 2 с системным WebView. Внутри неё запускается тот же интерфейс и игровой код, что и в веб-версии. При сборке Vite помещает актуальные HTML, CSS, JavaScript и локальные ресурсы внутрь приложения.

- **Windows и macOS:** приложение устанавливается на компьютер и запускает встроенную веб-версию. Для macOS выпускаются отдельные сборки Apple Silicon и Intel.
- **Android:** устанавливается APK. Игра запускается в Android WebView внутри нативной оболочки. Для сетевой игры требуется интернет; комнаты и синхронизация работают через Firebase.
- **iOS:** Tauri 2 в принципе поддерживает iOS, но в текущем проекте iOS-проект, подпись и сборка в GitHub Actions ещё не настроены. Готового IPA сейчас нет.

### Устройство

- Frontend обслуживается собственным протоколом `bandito://` (`frontendDist` — `bandito://localhost`). Rust-модуль `src-tauri/src/ota.rs` встраивает `build/` как offline fallback, поэтому Tauri build запускает `npm run build` (`beforeBuildCommand`) до компиляции Rust. Активная OTA-версия хранится в каталоге данных приложения.
- OTA-манифест и архив публикуются в GitHub Release `ota-latest`. Манифест подписан Ed25519; клиент проверяет подпись закреплённым публичным ключом и SHA-256 архива до распаковки.
- Архив распаковывается во временную версионную папку с ограничениями размера, числа файлов и путей, помечается как подготовленный и активируется только при следующем запуске. Когда обновление готово, приложение показывает постоянную плашку с кнопкой перезапуска: полный restart нативного приложения, а не reload WebView. Протокол проверяет незавершённый запуск до отдачи `index.html` и при сбое возвращает предыдущую версию; после успешного старта старые файлы удаляются.
- В манифесте обязателен `min_app_version`; текущая минимальная версия для OTA-перезапуска — 0.1.1.
- Firebase Realtime Database и Anonymous Auth работают через compat SDK из Google CDN; CSP в `src-tauri/tauri.conf.json` разрешает только нужные адреса.
- Для разработки — `npm run app:dev`; Vite-скрипт `dev:tauri` не открывает окно браузера и фиксирует порт 3000.

### Нужно ли пересобирать приложение после изменений?

**Для изменений интерфейса, JavaScript и локальных ресурсов пересобирать приложение вручную больше не требуется.** Нативная сборка содержит встроенную резервную версию, а новые веб-файлы доставляются через OTA: приложение скачивает и проверяет обновление при запуске, сохраняет его и активирует при следующем запуске. Текущая партия не прерывается. Изменения Rust-кода, Tauri, плагинов, разрешений и нативной конфигурации по-прежнему требуют новой сборки и установки.

Обычно это выглядит так:

1. Изменения отправляются в единственную рабочую ветку `main`.
2. GitHub Actions (Frontend checks) проверяет код, а Build Bandito apps, если настроен секрет подписи, публикует OTA-архив веб-интерфейса в GitHub Release `ota-latest`.
3. Приложение скачивает обновление в фоне, не прерывая текущую партию. Когда оно готово, в приложении появляется постоянное уведомление с кнопкой **«Перезапустить»**. Полный перезапуск приложения активирует новую версию и позволяет проверить её запуск.
4. Если менялась нативная часть, вручную запусти **Build Bandito apps**, скачай установщик или APK нужной платформы и установи его.

Повторная сборка также не требуется, если изменились только данные на сервере Firebase или содержимое удалённого сервиса, которое приложение получает из сети. OTA обновляет только веб-часть: HTML, CSS, JavaScript и ресурсы. Подпись манифеста и SHA-256 архива проверяются до установки; если новая версия не проходит запуск, приложение возвращается к предыдущей.

Для Android важно сохранять один и тот же release keystore: APK с тем же ключом можно устанавливать как обновление существующего приложения. Для macOS и Windows текущие сборки не подписаны сертификатами разработчика; на некоторых компьютерах ОС может показывать предупреждение при первом запуске.

### Настройка OTA-публикации

OTA-релизы публикуются в GitHub Release с тегом `ota-latest`. Для включения публикации в репозитории должен быть добавлен секрет Actions `OTA_SIGNING_PRIVATE_KEY`: это Base64-кодированный PEM Ed25519 private key. Закрытый ключ хранится только в GitHub Secrets; публичный ключ встроен в приложение. Workflow пропускает публикацию OTA, если секрет ещё не добавлен, но продолжает собирать приложения.

После добавления секрета можно вручную запустить **Build Bandito apps** с параметрами `build_apps = false` и `publish_ota = true`: это опубликует OTA без нативных сборок. Для постоянного уведомления и кнопки перезапуска нужна нативная версия **0.1.1**: её необходимо один раз собрать вручную с `build_apps = true` и установить поверх старой версии. Предыдущие нативные сборки не содержат команду перезапуска и не смогут применить это обновление автоматически. После установки 0.1.1 дальнейшие изменения веб-интерфейса будут доставляться автоматически. Веб-сайт GitHub Pages продолжает обновляться только из `main` и не зависит от OTA-релизов.

### Где скачать и что нажать

1. Открой [GitHub Actions — сборки Bandito](https://github.com/kipetsh/bandito/actions/workflows/build-apps.yml).
2. Выбери самый новый успешный ручной запуск **Build Bandito apps** для ветки `main`.
3. Прокрути страницу запуска до блока **Artifacts**.
4. Для полного набора скачай **Bandito-All-Platforms**. Если нужна только одна система, скачай соответствующий отдельный артефакт: **Bandito-Android-APK**, **Bandito-macOS Apple Silicon** или **Bandito-macOS Intel**.

Артефакты GitHub Actions хранятся 14 дней, поэтому готовые сборки нужно скачать до истечения срока хранения.
