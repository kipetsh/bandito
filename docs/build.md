# Сборка и ресурсы

## Команды

| Команда               | Назначение                                                                     |
| --------------------- | ------------------------------------------------------------------------------ |
| `npm run dev`         | Vite на `http://localhost:3000`, доступен из локальной сети                    |
| `npm run dev:local`   | Vite только на `127.0.0.1`, фиксированный порт 3000 (`strictPort`)             |
| `npm run check`       | Prettier и ESLint; каждый выводит полный список проблем, даже если другой упал |
| `npm run check:fix`   | автоисправление ESLint и форматирование проекта                                |
| `npm run test`        | исходные тесты, production-сборка и тесты сборки                               |
| `npm run test:source` | только исходные тесты                                                          |
| `npm run build`       | production-сборка в `build/`                                                   |
| `npm run test:build`  | проверка уже собранной `build/`                                                |
| `npm run preview`     | просмотр сборки                                                                |

Нужен Node.js 22.12 или новее (`.nvmrc`, `package.json`). Зависимости ставятся через `npm ci`; `postinstall` устанавливает pre-commit hook, который через `lint-staged` проверяет и форматирует staged-файлы.

Prettier: 4 пробела (JSON и YAML — 2), ширина 120, одинарные кавычки, LF. Legacy UI-файлы перечислены в `.prettierignore`, чтобы не плодить whitespace-only diff; их staged-правки форматируются всё равно.

## Что делает сборка

1. Vite собирает стили и весь JS из точки входа `js/main.js`. Модули импортируют друг друга через алиасы `#js/*` и `#assets/*` (subpath imports в `package.json`).
2. `tools/copy-static.mjs` копирует `resources/` (JSON колоды грузится через `fetch()`) и создаёт `build/404.html` для ссылок на комнаты — см. README, «Ссылки-приглашения».
3. `tools/optimize-images.mjs` конвертирует изображения в WebP через `sharp` и обновляет ссылки в собранных HTML, CSS и JS.

## Изображения

- Исходники лежат в `assets/images/` и не меняются; в игру попадают только оптимизированные копии из сборки.
- Любое растровое изображение готовится под Retina: исходник не меньше двойного CSS-размера, иначе на экранах 2x и 3x оно размывается. Сборка изображения не увеличивает, а только уменьшает слишком большие (до 1600 px по длинной стороне, фоны — до 2560 px).
- Сборка конвертирует растровые изображения в WebP, только если результат не больше исходника: PNG — без потерь (кроме логотипов, у них качество 76), JPEG — с качеством 85. Качество не снижается ради размера файла.
- Иконки интерфейса — встроенные SVG в `currentColor`: они не размываются при любой плотности экрана и меняют цвет вместе с темой. Если иконка всё же растровая, её прозрачные поля обрезаются, а визуальный размер считается по непустой области, а не по холсту. Контейнер не увеличивается ради компенсации пустых полей внутри файла.
- Иконки одиночной игры и мультиплеера в меню — SVG (`viewBox` 48 × 48 и 52 × 48) в одинаковой ячейке 64 × 64 CSS px с одинаковым зазором до текста: 16 px на широких экранах, меньше на узких.
- `index.html` заранее грузит фоны и логотипы, чтобы браузер начал получать их до разбора всех стилей.
