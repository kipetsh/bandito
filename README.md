### Цель игры

Бандито пытается совершить побег из тюрьмы. В этой кооперативной игре все игроки действуют сообща. Ваша цель — выкладывать карты так, чтобы заблокировать все туннели и не дать Бандито выбраться наружу.

### Содержимое

- 1 суперкарта (с Бандито в тюремной камере: сторона с 5 выходами и сторона с 6 выходами)
- 69 карт (туннели, развилки и тупики)
- 1 буклет с правилами

### Подготовка к игре

1. **Суперкарта:** найдите суперкарту и положите её в центр стола (вам понадобится просторный стол, так как лабиринт будет сильно разрастаться). Выберите уровень сложности:
    - Сторона с **5 выходами** — лёгкий уровень (standard).
    - Сторона с **6 выходами** — сложный уровень (hard).
      _(В веб-версии также добавлен ознакомительный режим на 2 выхода)._
2. **Колода:** перемешайте все остальные карты и положите их стопкой рубашкой вверх рядом с полем — это колода добора.
3. **Стартовая рука:** каждый игрок получает по **3 карты** на руку. Игроки могут смотреть свои карты, но не должны показывать их остальным.

### Ход игры

Игру начинает самый младший участник, затем ходы передаются по часовой стрелке. В свой ход игрок:

1. **Разыгрывает карту:** выбирает одну из карт в руке и выкладывает её на стол так, чтобы она соединялась хотя бы с одной уже лежащей картой.
    - **Золотое правило размещения:** выкладываемая карта обязана **идеально подходить** ко всем соприкасающимся с ней картам. Все линии туннелей на стыках должны точно совпадать (нельзя упирать открытый проход в глухую стену или стыковать проход с пустой стороной). Карты можно поворачивать горизонтально или вертикально; карты не могут перекрывать друг друга.
2. **Добирает карту:** после размещения карты игрок берёт верхнюю карту из колоды, чтобы в руке снова стало 3 карты.
3. **Если нет доступных ходов:** если ни одну из трёх карт в руке невозможно законно выложить ни в одной позиции, игрок имеет право сбросить все три карты под низ колоды добора и взять три новые карты. После этого ход завершается.
4. **Общение:** поскольку игра кооперативная, разрешено открыто обсуждать общую стратегию, направления и потребности команды, но **запрещено напрямую показывать свои карты** другим игрокам.

### Конец игры

Партия завершается в одном из двух случаев:

- **Победа игроков:** если вам удалось перекрыть абсолютно все выходы из туннелей (с помощью тупиков или закольцовывания путей), Бандито пойман — все игроки побеждают вместе!
- **Победа Бандито (поражение игроков):** если колода добора полностью закончилась, а на поле остаётся хотя бы один открытый туннель, Бандито успешно сбегает — все игроки терпят поражение.

## Правила цифровой адаптации

### Интерфейс партии

Рука, выбор положения карты, отмена и фокус, поле, камера, вид карт и подсказки описаны в [docs/game-ui.md](docs/game-ui.md).

### Правило сброса карт и таймера хода

Сброс карт из руки под низ колоды разрешён исключительно в ситуации, когда ни одну карту из руки невозможно выложить на поле ни в одной из четырёх ориентаций. Запуск одиночной партии из меню, пока открыто лобби кооператива, сначала выводит игрока из комнаты. Истечение таймера хода в кооперативе (60 секунд) приводит только к пропуску хода (очередь переходит к следующему игроку), карты в руке сохраняются. В идущую партию по коду или ссылке пускают только её игроков: после перезагрузки страницы игрок возвращается к своей руке. Когда игрок сам выходит из комнаты, остальные видят сообщение об этом, а его карты уходят под низ колоды; вернувшись по коду до конца партии, он добирает новую руку с верха колоды. Новые игроки подключаются после её завершения.

## Ссылки-приглашения в мультиплеер

У каждой комнаты есть собственная ссылка вида `https://kipetsh.github.io/bandito/K3F9QX`. При создании или подключении к комнате адресная строка обновляется без перезагрузки приложения. Кнопка в лобби копирует полную ссылку, а при её открытии Bandito автоматически подключается к комнате.

GitHub Pages не поддерживает серверные маршруты, поэтому production-сборка дополнительно создаёт `404.html` с тем же приложением. Он сохраняет адрес комнаты и задаёт правильную базу для ресурсов проекта — отдельная страница или перенаправление на главную не нужны.

## Пользовательские испытания

Игроки собирают свои раскладки в редакторе на настоящем игровом поле и публикуют их в общую библиотеку; редактировать и удалять можно только свои испытания. Подробности редактора и доступа — в [docs/challenges.md](docs/challenges.md).

## Структура проекта

- `index.html` — разметка экранов и подключение ресурсов.
- `css/` — дизайн-система: токены, базовые стили, компоненты и блоки экранов.
- `js/` — ES-модули: точка входа `main.js`, одиночная игра, Firebase-мультиплеер, редактор и библиотека пользовательских испытаний, настройки и уведомления. Модули импортируют друг друга через алиасы `#js/*` и `#assets/*` из `package.json`.
- `assets/images/` — логотипы, фоны и декоративные изображения.
- `resources/bandido-matrices/` — данные игровых карт.
- `vite.config.js` — настройки локального сервера и production-сборки.
- `tools/` — копирование runtime-ресурсов, оптимизация изображений, плагин Vite, подгоняющий толщину линий иконок Tabler под их размер и установка локального pre-commit hook.
- `tests/` — проверки ссылок, синтаксиса JS, данных колоды и собранного сайта.
- `src-tauri/` — нативная оболочка Tauri 2.
- `database.rules.json` — правила Firebase Realtime Database.
- `docs/` — подробная документация: интерфейс партии, испытания, сборка, CI, приложения.
- `package.json` и `package-lock.json` — команды проекта и зафиксированные версии инструментов.
- `build/` — результат сборки; генерируется автоматически и не коммитится.

### Разработка и проверки

Для разработки нужен Node.js **22.12 или новее**.

```bash
npm ci
npm run dev
```

Vite откроет локальную версию сайта на `http://localhost:3000` с автоматическим обновлением при изменениях.

Перед каждым коммитом запускай проверки и тесты:

```bash
npm run check
npm run test
```

`check` — Prettier (кроме заранее существовавших legacy UI-файлов) и ESLint. `test` — исходные тесты (ссылки, синтаксис JS, данные колоды, поведение модулей), production-сборка и проверка собранного сайта. Изменённые файлы автоматически форматируются локальным pre-commit hook.

Дополнительные команды:

```bash
npm run lint
npm run format
npm run build
npm run preview
```

Production-сборка находится в `build/`. Как она собирается и оптимизирует изображения — в [docs/build.md](docs/build.md).

### Публикация

Push в `main` публикует сайт в GitHub Pages и параллельно запускает проверки. Список workflow и порядок проверок — в [docs/ci.md](docs/ci.md).

### Где что менять

- Внешний вид и цвета — файлы в `css/`.
- Логику одиночной игры — `js/game.js`.
- Комнаты и сетевую игру — `js/multiplayer.js`.
- Выход из комнаты и возвращение в идущую партию (чистые изменения данных комнаты для транзакций Firebase) — `js/room-seats.js`.
- Настройки и переключение дня/ночи — `js/settings.js`.
- Открытие и закрытие модальных окон (настройки, подсказки «?», приветствие), возврат фокуса и запрет прокрутки страницы под окном — `js/modal.js`.
- Меню действий (кнопка и всплывающий список, как меню партии): открытие, закрытие действием, щелчком мимо и по Esc — `js/menu.js` со стилями `css/components/menu.css`.
- Анимация модальных окон — `css/blocks/modal.css`: статичный backdrop blur проявляется через `opacity`, анимация содержимого использует `opacity` и `transform`, без покадрового изменения радиуса blur.
- Состав колоды — `resources/bandido-matrices/cards.json`.

## Настольное и мобильное приложение

Bandito можно запускать как отдельное приложение на macOS и Android: нативная оболочка Tauri 2 с общей веб-кодовой базой, веб-часть обновляется через OTA. Сборка, подпись и обновления — в [docs/native-apps.md](docs/native-apps.md).
